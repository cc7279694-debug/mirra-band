# 05B.3 业务操作延迟与持久化优化

基线：`codex/module-05b-2-time-recovery` / `cf0328f5eade9427567647156d86b2503b6ad52e`。用户确认0.1.3/code4跨应用重进参考计时正常，保留USER_REPORTED_PASS。本轮仅腕端实验包，白色UI、旧记录、schema1、签名与命名空间继承，不进入05C或操作手机。

## 定位与最小合并提交设计

实际代码/受控后端计数：首次开始串行SELECT_BOOK→SELECT_ACTION→CONFIRM_START，3次save，共9读3写；FINISHED后开始含NEW_SESSION，4次save，共12读4写。每次save仍必须读取双槽、CAS/历史检查、写另一槽和精确读回。单次休息/继续/结束各3读1写。计时tick有全量snapshot和重复UI深拷贝/投影，需独立测量；以上是调用数，不是真机耗时。

增加专用`START_CONFIRMED`业务命令，不提供任意批处理。仅用户核对当前展示的第一动作并明确完成确认后，原transition在内存依次执行所需NEW_SESSION/CANCEL/SELECT_BOOK/SELECT_ACTION/CONFIRM_START，最后完整校验。只有最终状态交给原Owner及原journal保存一次。原中间命令继续可用；不删除第一动作校验，不改变持久格式。准备草稿不产生Session，counter只加1，Session ID仍由installationId+counter生成，既有pending保持原字节事实。写入/读回未确认前不发布新业务状态。

单次提交仍保留双槽读取、CAS、CRC、容量/结束预留、历史保护、原生未知锁存和精确读回。失败时Owner不接受内存候选；若物理写完成但回执失败，按原恢复语义核对，绝不报告业务成功。不缓存双槽代替CAS。

## 验证与响应

先RED再GREEN：EMPTY/IDLE/PREPARING/FINISHED的合法与非法确认、pending/计数器/容量、稳定ID、重复点击、隐藏/关闭、CAS冲突、双槽损坏、写失败/未知/读回不符。与原合法转换链最终结果比较，失败不得留下部分成功的准备记录。

按钮先发布忙碌状态并锁重复点击；普通tick改为只读时间投影，保留原异常记忆和参考标识，等待期间减少全量刷新。耗时诊断默认关闭，可在详情启用，仅内存有界数值/固定阶段名；不得记录书名/记录内容或写日志到业务槽。字段提交不是像素绘制证明。
