# Mirra Band 05B.1｜独立学习 UI / UX 设计与实施方案

> **交付性质：设计规格 + Codex 实施计划；不是已实现界面或测试通过报告。**
> 面向执行代理：实施时使用已安装的 `superpowers:executing-plans` 或等价的自主开发流程，内部按任务完成测试与提交；不要把内部任务拆成用户必须反复批准的验收关卡。

**Goal**：把 05B 的独立学习实验从长列表式功能页面，改为“打开即知道下一步、默认流程少点击、单屏有明确主次”的 Mirra 腕端体验。

**Architecture**：保留单一应用级 Local Owner、独立状态机、双槽存储与时间可信度规则；增加纯展示投影和轻量 UI 流程协调层。一个原生页面路由承载多个互斥视图，不重建业务 Owner，不引入第二套 Session 状态。

**Tech Stack**：Xiaomi Vela 原生 `.ux`、JavaScript、现有 aiot-toolkit 2.0.5、Node 测试；不引入 React、WebView、云服务或新 UI 框架。

**Spec**：本文件第 1–13 节为设计规格，第 14–18 节为实施、验证和交付计划；二者作为同一事实源使用。

**版本**：设计稿 v1.0，2026-10-12。所有未标记“仓库事实”的色值、尺寸、交互预算和验收门槛均为本方案提出的设计要求，不是目标固件已经验证的能力。

---

## 1. 目标、基线与这次纠正的方向

### 1.1 已确认的用户目标

用户已经自然体验 05B，反馈基本使用正常，但认为界面太简单、按钮缺少设计、操作步骤太多。用户授权设计师确定风格，要求参考 Mirra 手机端及成熟腕端产品的组织方式，并将在实施时另行提供与手机 Mirra 相同的原始 Logo。

本轮只回答两个问题：

- 打开手环以后，能不能更快进入、休息和结束一次阅读？
- 它能不能看起来像 Mirra 的同一家族产品，而不是存储实验控制台？

### 1.2 已核对的代码基线

| 对象 | 本轮核对的基线 | 用途 |
|---|---|---|
| Band 仓库 | `cc7279694-debug/mirra-band` | 唯一允许实施产品代码的仓库 |
| Band 分支 | `codex/module-05b-local-session` | 05B 基础 |
| Band HEAD | `6a220009d13a6172d92d2f375a2737d5b523ade3` | 开始实施时再核对最新状态，不回退新提交 |
| Android 参考提交 | `30a8af3fdea225cc96db6a360d71383a85b7ea39` | 只读查看 Mirra 样式，不修改手机 |
| 当前独立实验包 | `com.guanyi.mirra.band.localsessiontest` | 必须保持身份 |
| 当前实验版本 | `0.1.0 / code 1` | 新版建议 `0.1.1 / code 2`，以实际单调升级为准 |
| 构建入口 | `npm run build:local` | 不能误构建默认 demo 或 live |

仓库事实：当前 `.ux` 把实验说明、读写状态、书籍、动作、学习/休息时间、数字键盘、记录数量和诊断串在同一个长列表中。默认结束界面会直接出现数字键盘。现有状态机分别要求 `SELECT_BOOK`、`SELECT_ACTION`、`CONFIRM_START`，但这些内部操作没有必要各占一个用户页面。[S1][S2][S3]

### 1.3 修正此前方案的四处歧义

**不再设置一个只有“开始”按钮的首页，然后再去另一页确认动作。** 无活动 Session 时，首页本身就是选书与第一步准备的合并页。

**已有 FOCUS 时，不再让用户点“继续学习”才回到阅读页。** 打开直接恢复原阅读页面；只有 BREAK 的“继续学习”才真正改变业务状态。

**结束保持两次明确点击，不宣传成一键结束。** 从阅读页点“结束”进入确认，再点“结束并保存”；默认不出现键盘。不增加第三次弹窗，也不牺牲防误触。

**技术说明退后，不等于不确定时间和保存失败也退后。** 一般实验说明可以缩短；影响数据真假的警示必须与对应数字、按钮一起可见。

## 2. 不变的产品合同与明确不做的内容

### 2.1 必须保留

每次正式阅读前必须由用户明确确认第一步已完成。选择/预览动作不等于完成动作。应用退出、息屏或返回表盘不自动结束 Session；休息计时归零不自动恢复。结束页码允许为 `null`，不能以起始页、上次页或 `0` 代填。只有可靠写入并读回后才能展示保存成功。

本轮仍只使用测试书籍，所有独立记录仍只在手环本地。没有真实主线目录同步，没有手机导入，没有同步 ACK。页面不能显示“主线已同步”“已同步到手机”“正在上传”等不存在的状态。

手机没有参与分心监测，腕端内部的 `FOCUS` 对用户显示为“阅读中”，而不是“已验证专注”或“深度专注”。时间观察值也不能改名为有效专注时长。

### 2.2 禁止的范围扩张

不修改 Android、Room、Migration、手机备份和统计；不实现 05C–05E；不改变存储 schema、namespace、CRC、序列、容量、历史保留、时间算法或第一步规则；不引入后台常驻、通知、振动、复杂图表、打卡积分或能力评分。

不切换正式包名，不把独立实验变成正式 Mirra；不覆盖 Module 03/04 的在线伴侣与遥控能力。不因为用户提供了正式 Logo，就去掉“实验版”身份。

### 2.3 本轮成效目标

| 场景 | 新版目标 | 点击口径 |
|---|---|---|
| 打开已有阅读 | 直接恢复阅读页 | 0 次额外点击 |
| 默认书籍与短动作开始 | 展示动作后，点“已完成，开始” | 1 次主操作，不含现实中完成动作 |
| 更换书籍再开始 | 点书籍、选书、确认开始 | 3 次；列表滚动另计 |
| 更换动作再开始 | 点更换、选动作、确认开始 | 3 次 |
| 开始休息 | 点休息、选 5 或 10 分钟 | 2 次 |
| 结束休息 | 点继续学习 | 1 次 |
| 不填页码结束 | 点结束、点结束并保存 | 2 次 |
| 填页码结束 | 点结束、补页码、输入、保存 | 3 次操作 + 数字输入 |

这些是设计目标，交付必须按实际界面核对。长文本滚动、存储错误和用户主动修改不能偷偷排除后宣称所有情况都“一键”。

## 3. 视觉方向：Mirra Blue · 腕端夜色

### 3.1 参考方式

Mirra 手机实际代码中，Blue 主体是灰白背景，保留柔和蓝 `#6598E8` 和强行动蓝 `#386FBE`；另有 Night 深色方案。因此不是把手机整页等比例缩小，也不是宣称手机原版一直是黑底。[S4]

本轮沿用腕端现有深墨背景，并借用 Mirra 的蓝色行动语言、圆角和克制的层级。参考 Apple 腕端设计的“短交互、低导航层级、重要信息一眼可见”，不移植 watchOS 的数码表冠、系统材质、SF 字体、通知或 Always On 能力。[S6]

### 3.2 选定与放弃

| 路线 | 决定 | 原因 |
|---|---|---|
| 深墨底、安静留白、蓝色主动作 | 采用 | 继承腕端现有语言，适合突出动作和计时 |
| 满屏卡片、封面、渐变、光晕 | 不采用 | 会继续挤压内容与触控空间 |
| 高成本玻璃模糊、动态折射 | 不采用 | 不是本轮产品价值，也不假定原生能力 |
| 照搬手机灰白整页 | 不采用 | 保留品牌家族感，而不是机械复制媒介 |
| 圆环包住计时器 | 不采用 | 没有计划学习目标，不制造完成比例的错觉 |

### 3.3 视觉纪律

每个核心页面只有一个高对比主动作。准备页允许一张第一步重点卡；阅读页让大数字直接在背景上呈现，不再层层套卡。普通辅助内容以平面行组织。

不加励志口号、头像、书籍封面、成就、日历和装饰性统计。不要同时把计时器、每个按钮、每个状态都涂成蓝色。蓝色只表达当前最重要的信息或可执行动作。

## 4. 信息架构：业务状态不变，界面按任务组织

### 4.1 页面视图，不等于新增九层导航

| UI 视图 | 职责 | 何时出现 |
|---|---|---|
| READY | 默认书籍 + 第一步 + 开始 | 无活动 Session，或 PREPARING |
| BOOK_PICKER | 更换测试书籍 | 用户主动点书籍行 |
| ACTION_PICKER | 查看和选择替代动作 | 用户主动点更换动作 |
| READING | 阅读计时与休息/结束 | 业务状态 FOCUS |
| BREAK_PICKER | 选择休息 5/10 分钟 | 点击休息后 |
| RESTING | 休息剩余时间与继续/结束 | 业务状态 BREAK |
| FINISH_REVIEW | 无键盘的结束确认 | 点击结束后 |
| PAGE_EDITOR | 可选数字键盘 | 点击补充页码后 |
| SAVED | 本地保存结果 | FINISH 已读回确认 |
| DETAILS | 原始详情、限制、诊断、退出 | 次级入口 |
| STORAGE_NOTICE | 阻止危险操作的存储提示 | 必要时替换主要内容 |

根路由继续 `pages/LocalSession`。视图在同一原生页面内互斥渲染；不要求为每个视图新增系统路由或业务 Owner。

### 4.2 首屏恢复优先级

1. 尚未读到持久化结果：显示“正在读取”，不先闪现空首页，不允许开始。
2. Owner 为 BLOCKED/UNCERTAIN/CLOSED 或证据准入关闭：显示相应安全界面，不能当作无记录。
3. 已存在 FOCUS：直接 READING。
4. 已存在 BREAK：直接 RESTING；不分倒计时是否归零。
5. PREPARING：READY，恢复已保存书籍和动作。
6. FINISHED_PENDING_SYNC：应用冷启动进入 READY，并提示“已有 N 条本地记录”；刚成功结束则进入 SAVED。
7. IDLE/EMPTY：READY，展示建议书籍/动作，但不自动写数据。

“已恢复阅读”不需要弹窗确认。恢复出来的时间若不确定，展示不确定状态，但不删除或重新开始 Session。

### 4.3 默认书籍与动作

默认书籍优先级：当前 UI 已明确选定的有效草稿 → 持久化 preparation → 最近一条本地完成记录对应的仍存在测试书籍 → 测试目录第一项。

动作优先级：UI 当前明确选择 → 同一本书已保存 preparation 的动作 → 该书已有可用预设第一项。

这里的最后一级只是**推荐预览**，不是已经选择或已经完成。用户点击完整可见的“已完成，开始”，才同时接受本次显示的书籍/动作并确认自己做完了这一步。不要在 `onShow`、默认取值或倒计时中静默确认。

不新增最近书籍偏好数据库；已有完成快照足够作为默认建议来源。未来有真正目录同步时再替换数据来源，不在本轮显示不存在的主线。

## 5. 页面级规格

以下所有数字均为布局示例，不是用户真实学习记录。测试包展示真实 TEST_BOOKS 内容，不把示例标题写死为手机书名。

### 5.1 READY：首屏就是准备，不再多一个欢迎页

**视觉焦点**：第一步动作和“已完成，开始”。

顶部放小 Logo、Mirra 和清楚但克制的“实验”标记；不做大 Logo 开屏动画。书籍区域为整行可点，显示书名与测试起始页；缺页码显示“未设置页码”，不填虚构进度。

第一步区域明确写“先完成这一步”。正文优先完整展示短动作；右上角“更换”是次级操作，点击区域不小于 40×32 设计单位。底部主按钮为“已完成，开始”。

默认路径不再经历“开始首页 → 选书 → 选动作 → 返回 → 开始”。可选的书籍和动作选择只在需要时打开。

**短文本基准布局**：顶部标题区、书籍行、动作卡、底部主按钮均在一屏；动作正文原则上为 2 行，约 18 个全宽字符。这个数量仅用于挑选长文本布局，不作为精确测字依据。

**长文本布局**：不压字号、不强制跑马灯。正文放入可滚动内容区，完整确认按钮在完整动作正文之后；仍是一页，不增加“阅读动作后返回确认”的冗余路线。无需用计时器或滚动到底的埋点声称用户已经阅读，只保留其明确确认。

**未保存/忙碌**：显示“正在开始…”并锁住所有会写入的按钮；不能先切到 READING。详情/系统退出仍遵循原生命周期边界。

### 5.2 BOOK_PICKER：选择即返回，无额外确认

显示当前 TEST_BOOKS 列表，整行可点。每行只包含书名、测试起始页和选中标记；选中依靠标记及色彩共同表达。

常规行高 48 设计单位，长标题可扩到 64；至少两行标题。点一项后返回 READY；这是 UI 草稿选择，不创建正式 Session，不开始计时。退出选择页不改变原书籍。

本轮不增加搜索、排序设置、封面、标签过滤和真实书籍管理。

### 5.3 ACTION_PICKER：动作完整可见，选择不等于完成

当前书籍及可选预设动作按清楚的行展示。行高按完整文本自适应，不为“整齐”切掉动作主体。

点击动作即返回 READY；不再单独点“保存动作”，也不自动执行 CONFIRM_START。返回 READY 后用户仍需实际完成并点主按钮。

原文不得为了排版而改写后写回数据。显示完整、换行、字号层级可以改，动作含义与存储文本不能被样式层修改。

### 5.4 READING：0 次点击恢复，时间与休息是主角

布局示意：

```text
阅读中 · 实验                详情
         测试书籍 · 阅读练习

               25:36
          阅读计时 · 参考值

            仅本地 · 未监测

        [   休息   ] [ 结束 ]
```

主数字使用已有 `observedFocusMs` 的非空观察值，明确排除休息。不得使用整个 Session 墙钟差替代。`trustedFocusMs=0` 不显示为“已验证专注 0 分钟”。

“休息”为蓝色主按钮；“结束”为深色次按钮。两个按钮都在首屏底部，无需滚动查找；结束不是红色危险按钮，也不能使用小叉代替明确文字。

已存在 FOCUS 时重开直接到本页，不显示“继续学习”门槛，不发送 RESUME，不多建区间。

### 5.5 BREAK_PICKER：只在点休息后出现

标题“休息多久？”，显示两个足够大的选项：“5 分钟”和“10 分钟”。选择本身就是明确提交，不再加确认弹窗。两项同级、不要无依据预选其中一个后自动倒计时。

在选择页停留期间，底层仍然是 FOCUS；只有 `BEGIN_BREAK` 写入确认后进入 BREAK。点返回不改变计时。这里仍是两次点击，不宣传休息操作变成一次。

### 5.6 RESTING：继续才意味着改变状态

主数字显示已有 `breakRemainingMs`，旁边标“计划剩余 · 参考值”。0 时用“休息时间已到”替代巨大的 00:00；主按钮仍然是“继续学习”，不会自动转为 FOCUS。

底部主按钮“继续学习”，次按钮“结束”。点击继续仅提交一个 RESUME；选择结束允许直接在休息中进入结束确认，不要求先恢复阅读。

若剩余时间为 null：显示“时间待核对”，保留“休息中”和“继续学习”。时间不确定本身不等于不能保存；能否写入仍由 Owner 的真实状态决定。

### 5.7 FINISH_REVIEW：默认不出现键盘

阅读页点“结束”后显示：当前书籍、阅读观察时长、休息观察时长、一行“页码：不填写”和次级“补充页码”。主按钮“结束并保存”。

此页只是确认视图：不冻结时间、不记录结束时刻、不关闭区间。最终 FINISH 点击时才按原业务获得时间并持久化。界面可用一行“确认后结束”说明，不必放技术长文。

主按钮发送 `FINISH(endPage:null)`。保存成功后再进 SAVED；失败则保留可恢复的界面、输入和最后确认状态，不显示对勾。

**这是防误触的两次点击**：结束 → 结束并保存。移除数字键盘是减阻，不是取消结束确认。

### 5.8 PAGE_EDITOR：需要时才付出输入成本

首次进入必须为空，不预填起始页或上次页。继续沿用 05B 正整数 1–999999 / 可空的校验；测试书没有总页数时不发明上下限关系，不在此轮假装做正式进度同步。

数字键盘为 3×4，最后一行“留空 / 0 / 退格”。“留空”只清理输入；“保存”才发送 FINISH。顶部显式“返回”丢弃本次键盘编辑，回到不填页码的 FINISH_REVIEW；不悄悄保存部分输入。

推荐无滚动布局预算：上方 32 高工具栏包含“返回”和蓝色“保存”；其下 28 高页码显示；四行 32 高按键、行间距 4；底部保留安全余量。这里工具栏保存按钮为紧凑版，仍达到 32 高触控下限。无需让用户滚过键盘后再找保存。

小范围全角/emoji 不允许进入数字值；格式错误就在输入附近说明。不得因为换视图或每秒刷新把数字草稿清空。

### 5.9 SAVED：强调“存到了哪里”，不混淆同步

标题“已存到手环”，可以配一个小的本地成功对勾。阅读和休息均保留时间参考标签；null 用“未能确定”，不能替换为 0。

结束页码有值才显示；空值以一行“未填写页码”说明。下方显示“仅本地 · 尚未同步”。详情中明确“本实验尚未接入手机同步”。

只保留一个主按钮“完成”，返回 READY。无需同时出现“完成 / 再学一次”两个作用接近的按钮。“完成”只是 UI 导航，不能删除 pending，也不必立即执行 NEW_SESSION。下次明确开始时再按现有状态机推进。

### 5.10 DETAILS：把说明收好，而不是删除

展示当前状态、所选书籍/动作原文、记录来源、时间原因、已保存数量、版本和必要诊断。使用只读投影，不新增删除、ACK、导出和同步操作。

可以展示当前已存在 pending 的简短只读摘要；最多按照原有 8 条设计上限读取，不做完整历史系统、搜索或编辑。若这会明显扩大 UI 工作，优先保留当前/最近记录和数量，不能阻碍主流程交付。

“退出应用”可放在这里，沿用现有退出接口。正常系统返回/退出不发送 FINISH，不追加恢复事件，不重置计时。

## 6. 精确视觉系统

### 6.1 单位与画布

目标物理画面 336×480；沿用 `config.designWidth:168`，名义设计画布为 168×240。本文件用 **u** 表示 Vela 设计单位；在该目标上 1u 对应约 2 个物理像素。实现写 Vela `px`，不是把 Android dp、Apple pt 或浏览器 CSS 像素直接搬来。[S7][S8]

这是当前目标的尺寸基准，不是所有固件都保证无系统占位。若实际内容区高度不同，应优先保持触控区和文字，允许内容区滚动；不要压扁按钮、裁切警告或修改全局 designWidth 迁就一页。

READY 短内容参考预算为：header 12–44；book 48–88；action 94–170；CTA 180–220。动作卡短文本两行可用；长动作转入全文滚动变体，不能硬塞到76u。

## 7. 按钮、图标、触控和动效

### 7.1 三层按钮

**主按钮**：蓝色实底、深色文字、40u高、16u圆角。用于确认开始、继续、保存。全屏最多一个最强主操作；休息时长选择是同级选项，不搞两个竞争的主 CTA。

**次按钮**：surface填充、主文字或次文字、12u圆角。用于结束、补充页码。可点击性依靠完整触控表面，不靠一条很细的描边。

**轻按钮**：视觉上只保留短文字或小图标，但点击范围至少40×32u。用于更换、返回、详情。视觉小不等于触控小。

### 7.2 状态反馈

| 状态 | 呈现与行为 |
|---|---|
| normal | 清晰角色与可点击范围 |
| pressed | 立即颜色变化，不移动周围布局 |
| disabled | 降低强调度并在相邻位置给原因；事件处理器也拒绝，不能只有灰色 |
| submitting | 保持按钮尺寸，短文案“正在开始…”/“正在保存…”，拒绝双击 |
| success | 只有持久化确认后才切换业务视图 |
| failure | 保留当前可恢复内容和输入，显示可行动说明 |

只使用目标Vela已验证的状态/事件能力；不支持按压动画时用颜色状态即可。禁止为了“触感”新增无依据的振动。

### 7.3 手势与返回

主要操作都必须有可见文字入口，不只靠滑动或长按。系统侧滑返回保持原行为；额外轻按钮服务于容易迷路的选择/输入视图。

选择、详情和结束确认可以返回，不能因返回而自动写 Session。忙碌期间阻止并发业务写入，但不创建阻止用户正常退出的永久锁；沿用原生超时及恢复限制。

页面切换后从当前页面顶端开始；计时刷新时保持滚动位置、选项和键盘输入。优先互斥挂载视图容器，不依赖未经核实的滚动API。返回详情可恢复同一视图的正常位置，但不同业务页不能复用错位列表偏移。

### 7.4 动效

默认不新增持续动画。可选的按压/切换过渡目标80–160ms，只在原生支持且不影响响应时启用；不支持就直接切换。不做数字滚轮、呼吸灯、全屏发光、倒计时闪烁或模拟实时后台运动。

## 8. 时间、保存、容量与错误的信息层级

### 8.1 时间是最不能被“美化”的地方

| 原始事实 | 主界面 | 详情 | 不能做 |
|---|---|---|---|
| 有观察值，原因只有 WALL_ONLY | 大数字 + 紧邻“参考值” | 墙钟观察、未验证 | 去掉参考标签，叫有效专注 |
| 当前显示指标为null | `--:--` + “时间待核对” | OWNER_CHANGED/回退/缺失等具体原因 | 用0或最后一次数字继续走表 |
| 只有其他区间存在异常 | 当前数字仍带参考标签，同时提示记录含不确定区间 | 分别解释学习/休息 | 用整体布尔值把所有显示误作准确 |
| 休息剩余为0且可观测 | “休息时间已到” | 实际休息仍在累计 | 自动RESUME |
| 休息剩余为null | “时间待核对”，保留休息状态 | 原始边界保留 | 推断已经到时 |

原逻辑中跨owner可使观察值为null；本轮不能修改 `duration()` 或重新用 Date.now 减原始起点绕过它。改善显示不等于解决时间源可靠性。[S3]

### 8.2 提示优先级

P0：IO结果不确定、存储不可读取、身份/序列冲突、未知schema。直接占据主要内容并限制业务动作。

P1：读取了上一有效快照，或当前时间指标不确定。就近告知，不用大段堆满屏幕；必要时在恢复后先让用户核对状态。

P2：实验版、未监测、仅本地、未同步。保留清楚的小标签和详情，不每页重复三段长文。

**存储RECOVERED处理**：增加只在UI层的“核对恢复状态”提示。用户确认的是看到了所恢复的书籍/状态，不是确认数据绝对完整或确认时间正确。不得静默称作“全部恢复成功”。无需改核心 Owner；确认不应创建学习事件或改写时长。

### 8.3 固定文案

| 场景 | 建议主文案 | 补充说明 |
|---|---|---|
| 正常准备 | 先完成这一步 | 已完成，开始 |
| 正常阅读 | 阅读中 | 阅读计时 · 参考值 |
| 暂存 | 正在保存… | 暂不能重复操作 |
| 成功 | 已存到手环 | 仅本地 · 尚未同步 |
| 读写未知 | 保存结果待核对 | 请退出后重开查看；暂不继续写入 |
| 普通可恢复读取失败 | 暂时无法读取 | 重新读取 |
| 回退快照 | 已读取上一份记录 | 请核对当前状态，最近变化可能未保留 |
| 容量不足 | 本地空间预算不足 | 已有记录不删除；本次操作未保存 |
| 时间未知 | 时间待核对 | 阅读状态保留，时长暂不确定 |
| 无手机同步 | 本实验仅在手环保存 | 后续版本接入手机同步 |

不能把“已读取上一份记录”说成“所有数据都安全”。不得添加“去同步即可解决”按钮，因为该版本没有同步能力。

### 9.1 使用位置

不为了Logo新增全屏开屏页，不要求用户每次等品牌动画。

## 10. UI编排与现有命令的安全对应

### 10.1 业务与UI双层状态

`document.state` 只能由现有 Owner 的已确认持久化结果提供。`ui.view`、书籍/动作候选、页码输入、选择页返回目标为内存UI草稿。

不向document新增 `viewMode`、`recentBook`、`dismissedHint` 字段，不修改canonical schema。UI草稿丢失时从最后持久化事实恢复，不补造操作。

### 10.2 默认一键开始如何不绕过第一步

用户点击之前：只展示推荐，不写文件。

用户点击时：捕获不可变的可见书籍ID、动作ID与文本、当前业务身份/序列。锁住本次UI提交。根据最后已确认状态，顺序调用已有动作；每一步检查返回快照确实符合预期，才继续。

| 起始状态 | 命令顺序 |
|---|---|
| IDLE或EMPTY | SELECT_BOOK → SELECT_ACTION → CONFIRM_START |
| FINISHED_PENDING_SYNC | NEW_SESSION → SELECT_BOOK → SELECT_ACTION → CONFIRM_START |
| PREPARING且书籍相同、动作已相同 | CONFIRM_START |
| PREPARING且同书、动作不同或空 | SELECT_ACTION → CONFIRM_START |
| PREPARING且用户明确改为另一书 | CANCEL_PREPARATION → SELECT_BOOK → SELECT_ACTION → CONFIRM_START |
| FOCUS / BREAK | 拒绝开始编排，返回当前活动学习 |

命令链是一次可见用户动作下的内部顺序，不宣称整个链是新增原子事务。任一步失败，停止后续动作，保留最后确认状态和当前可用UI草稿；不得自行清库、回滚历史或自动再次开始。中途退出后重进如果仅剩PREPARING，仍需用户再次明确确认，不能后台补执行CONFIRM_START。

### 10.3 关键实现细节

`owner.dispatch()` 返回Promise resolve **不代表业务成功**。现有Owner可能将错误保存在返回快照中。执行层必须检查 `status`、`errorCode`、`document.state`、预期对象和 `sequence`，不允许 `.then(() => showSuccess())`。[S5]

UI提交锁跨越整条命令链，不只给按钮加300ms防抖。关闭/离开视图使未启动的后续动作失效，但不能假装取消已经进入原生IO的动作；重进必须重新读取。

写入前后逐步核对显示对象；每秒刷新、目录预览或旧回调不得把被确认的动作替换成另一个动作。禁止同时维护两个LocalOwner来“分离页面”。

### 10.4 结束编排

`showFinish`、`openPageEditor`、数字输入、返回均不发FINISH。唯一FINISH入口是明确的“结束并保存”或PAGE_EDITOR的“保存”。

提交时捕获当前Session身份、endPage草稿；成功需确认原Session进入pending、active变为null、返回状态可靠。按钮再点、页面重进或晚到回调不能增加第二条pending。

本轮不新增结束后编辑。用户填写错误可暂保留为实验记录，不通过UI设计偷偷添加改历史能力。

## 11. 单页实现与组件边界

### 11.1 建议结构

```text
src/
  lib/
    local-presentation.js     # 纯投影：状态/时长/错误 → 文案、按钮与样式角色
    local-ui-flow.js          # UI草稿、返回、顺序命令、提交锁；不拥有持久化
  ui/
    local-tokens.js           # 颜色、尺寸、字阶的单一设计来源
  common/
    local-theme.css          # 仅local视图引入，不能改坏live/probe
    local-brand/             # 用户Logo及本profile派生图，提供后接入
  pages/LocalSession/index.ux # 根生命周期 + 互斥原生视图，继续单路由
  local-app.ux               # 原有app owner保留，原则上不改业务构造
```

可按现有Vela支持拆出少量复用组件，如ActionButton和TimerHero；这不是必须创建一个组件库。原生组件拆分不能引入额外Session Owner或自己的后台计时器。

### 11.2 建议接口

这些是新增UI层的实施约定，不是声称仓库已经存在：

```javascript
// local-presentation.js：纯函数，无IO、无Date.now、无业务dispatch
presentLocal(ownerSnapshot, uiState, catalog, brand) => LocalViewModel
formatObservedDuration(valueMs, options) => { valueText, qualifier, isUnknown }
resolveReadyPreview(ownerSnapshot, uiState, catalog) => Preview

// local-ui-flow.js：仅调用已存在的owner.open/dispatch/snapshot
createLocalUiFlow({ owner, catalog, requestExit }) => {
  getState(), subscribe(listener),
  show(), hide(), back(),
  chooseBook(bookId), chooseAction(actionId),
  confirmStart(visiblePreview),
  openBreakPicker(), beginBreak(minutes), resume(),
  openFinishReview(), openPageEditor(), setPageDigits(digits),
  finish(endPage), done(),
  openDetails(), reload(), exit(), dispose()
}
```

`LocalViewModel`至少提供当前互斥视图、书籍/动作原文、计时值及紧邻标签、主/次按钮角色与可执行标记、存储告警、实验标记和本地记录数量。

`show()`只打开/读回并订阅；`hide()`停止视图刷新并使未提交后续UI动作失效，不close业务Owner；`dispose()`仅清UI资源。App真正销毁仍由原来的local-app关闭Owner。

### 11.3 原生样式限制

Vela使用原生组件和自己的样式子集。采用已知可用的div/text/list/image、Flex、class和内联样式，圆角必要时同时设置border-width/border-color。[S8][S9]

不要假定浏览器后代选择器、CSS变量、CSS Grid、固定定位、backdrop-filter、sticky、tabular-nums都支持。Token可以由JS绑定或本地小脚本生成普通CSS；无需引入Sass/Tailwind/新的构建依赖。

## 12. 性能与可达性

前台显示继续最多每秒刷新计时；页面隐藏就停视图刷新。时间标签变化不重建整个选择列表和数字键盘，不重置滚动位置，不创建每页自己的独立存储读取循环。

短动作准备、阅读、休息、无页码结束确认，主动作必须首屏可达。长内容使用可滚动主体；绝不通过降低到不可读字号实现“全在一屏”。

建议颜色对比作为自动化设计检查：正常正文/交互文字目标至少4.5:1，关键非文字状态目标至少3:1；这是项目QA目标，不是宣称已通过完整无障碍认证。禁用态也要看得见，并且说明为何不能点。

不只靠颜色区分学习/休息/异常；按钮必须有文字。恢复/保存提示不在几百毫秒后自动消失。系统字体、实际中文字宽、触控区和圆角需要原生环境核对。

不把Vela限制当作做长列表控制台的理由，也不为炫技牺牲稳定性。
