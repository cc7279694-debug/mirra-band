# Mirra Band 05E — Product Baseline V1
状态：ACCEPTED / FROZEN — 产品决策已确认。
确认日期：2026-10-15（Asia/Shanghai）。这是用户冻结的产品口径，不是05E实现/发布/真机通过。

## 1. 核心目标
将手机与手环的阅读记录整合到 Mirra 的统一阅读历史、书籍阅读历史和描述性统计中。两端原始记录分别保留，通过只读投影统一展示，不将手环记录伪装成手机 Session。

## 2. 已冻结统计口径
采用方案A：手环参考阅读单独展示，双端合格区间可去重汇总，不加入有效专注。
- 手机有效专注与 Start / Maintain / Recover 保持现有计算口径。
- 手环 FOCUS 合理时长显示为参考阅读，BREAK 不计入阅读。
- 手环未经验证的墙钟时间不得升级为可信专注。
- 可比较的手机阅读区间和手环 FOCUS 区间，按区间并集计算去重参考阅读。
- 不允许简单相加形成虚高时长。
- 跨设备时钟不可比较、时间缺失、回退、异常跳跃或结构不完整时，不生成无法证明的双端总量。
- 参考时长暂不参与原有阅读速度、剩余时间和阅读节奏洞察模型。
- 不改变原有手机监测覆盖、有效专注阈值和统计公式。

## 3. 阅读历史
统一展示手机与手环记录，来源明确区分。每条腕端记录必须保留书籍快照、第一步动作、可空结束页码、完整阅读/休息区间以及时间可信度。统一历史采用来源复合身份，防止手机 Session ID 与腕端 Session ID 冲突。保持分页稳定、按真实结束时间排序。未知结束时间不得使用手机接收时间冒充。书籍删除或状态变化不能导致已导入腕端原始记录消失。

## 4. 书籍进度
同一真实书籍通过稳定ID关联。仅对合法且可安全应用的结束页码，按max(currentPage,endPage)推进。书籍缺失、页码越界、活动Intent/Session冲突等情况应保留原始记录并暂缓推进。结束页码为空不推进进度；重复导入和重复协调不得引起进度回退或重复业务副作用。

## 5. 数据与备份
保留05D Room v5的不可变腕端原始记录表。优先通过可重建的只读投影实现统一查询；需要新增索引或Room v6时必须经过独立评估。任何数据库变更均需同步完成迁移、Full Backup兼容及恢复测试。不得改变原始腕端记录、删除手机Session、修改监测算法或丢弃未确认记录。

## 6. 实施顺序
- 05E-0：架构与数据准入审查。
- 05E-1：统一阅读历史查询、来源标识与分页。
- 05E-2：手环记录详情及单书阅读历史。
- 05E-3：合法页码推进与活动工作流保护。
- 05E-4：参考阅读统计、双端区间去重及异常处理。
- 05E-5：数据库与备份兼容、全量回归和自然使用验收。

## 7. 开发门禁
05D开发已经完成，但真实无线记录同步与手机实际数据库升级仍待用户反馈。当前允许05E-0设计、代码核查、模型推演和技术方案审查；未取得05D必要真机结果前，不将05E实施视为可直接发布。涉及Room迁移、真实数据操作、正式包安装、归档清理等高风险事项，必须单独经过安全审查和相应授权。Codex负责执行，ChatGPT负责架构审查与阶段验收。不自动进入其他模块，不自动合并main。

## 8. 验收标准
最终用户能够在手机Mirra中同时查看两端阅读历史、来源与时间性质，正确获得合法书籍进度和参考阅读统计。重复同步、跨端重叠、备份恢复、时间异常均不能导致记录丢失、统计虚高或有效专注指标污染。产品统计口径已经冻结，不再因一般代码实现便利而随意改变。
